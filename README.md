# LearnLoop

A course-grounded learning application with three backend agents: **Expert**, **Tutoring**, and **Assessing**. The interface calls the last two **Tutor** and **Reviewer**.

For a class presentation, start with the [agent architecture and code walkthrough](backend/docs/agent-architecture.md). It maps the proposal to executable code, explains the class concepts demonstrated, and distinguishes implemented behavior from planned work.

## Local setup for teammates (SQLite)

SQLite is the default database. Application records, uploaded documents and embedding vectors live in `backend/data/learnloop.db`; sqlite-vec is installed with the Python dependencies. Each teammate has their own local database. No Docker, PostgreSQL, Qdrant server or separate SQLite installation is required.

### 1. Install prerequisites

- Python 3.12, available as `python` in your terminal.
- Node.js with npm (the installed Next.js version requires Node.js 20.9 or newer).
- Ollama, running locally or on a reachable server, for embeddings.
- An OpenRouter API key with access to the model configured in `OPENROUTER_MODEL`. Real agent workflows use paid model calls.
- Optional: Poppler (`pdftoppm` on PATH) for original PDF slide images. Extracted text works without it.

The commands below use Windows PowerShell. Open a terminal in your cloned project folder, the directory containing this README.

### 2. Initialize the backend

```powershell
python --version
node --version
npm --version
.\backend\scripts\development\setup.ps1
```

The script creates `backend/.venv`, installs `requirements.lock.txt`, creates `backend/.env` from the example with a random `API_TOKEN`, and applies database migrations. It preserves an existing `.env`. If PowerShell blocks the script, use `powershell -NoProfile -ExecutionPolicy Bypass -File .\backend\scripts\development\setup.ps1` for this invocation.

Edit `backend/.env` before starting services:

| Setting | Value / action |
| --- | --- |
| `DATABASE_URL` | Keep `sqlite:///data/learnloop.db`. Relative paths resolve from `backend/`. |
| `API_TOKEN` | Keep the random value generated by setup. Copy this same value into the frontend configuration below. |
| `LOCAL_OWNER_ID` | Keep `local-owner` for your local workspace; keep it stable to retain access to your records. |
| `OLLAMA_BASE_URL` | Keep `http://localhost:11434` for local Ollama, or set your reachable server URL. |
| `OLLAMA_EMBEDDING_MODEL` | Keep `bge-m3`. |
| `OLLAMA_EMBEDDING_ENDPOINT` | Keep `/api/embed`. |
| `EMBEDDING_DIMENSIONS` | Keep `1024` for `bge-m3`; changing the model/dimensions requires rebuilding stored vectors. |
| `OPENROUTER_API_KEY` | Fill in your own OpenRouter key. |
| `OPENROUTER_MODEL` | Defaults to `openai/gpt-6-luna`; choose a model your OpenRouter account can access. |

SQLite stores and searches vectors; Ollama still generates them. For local Ollama, start the Ollama app/service and download the embedding model:

```powershell
ollama pull bge-m3
```

For a remote Ollama service, its operator must install the model on that server. If you already use PostgreSQL, follow the [migration guide](backend/docs/sqlite-development.md#import-an-existing-postgresqlqdrant-workspace) before changing the database URL.

### 3. Configure the frontend

From the project root:

```powershell
Copy-Item frontend/.env.example frontend/.env.local
```

On first setup, edit `frontend/.env.local`:

```dotenv
LEARNLOOP_BACKEND_URL=http://127.0.0.1:8010
LEARNLOOP_API_TOKEN=PASTE_THE_API_TOKEN_FROM_BACKEND_ENV
```

`LEARNLOOP_API_TOKEN` must exactly match `API_TOKEN` in `backend/.env`; it is not your OpenRouter key. These frontend variables are server-only. Never prefix credentials with `NEXT_PUBLIC_`. For an existing checkout, edit the existing `.env.local` rather than overwriting it.

### 4. Start all three processes

Open three terminals in the project root. Keep all three running.

**Terminal 1 — API:**

```powershell
cd backend
.\.venv\Scripts\python -m uvicorn learnloop.main:app --host 127.0.0.1 --port 8010
```

**Terminal 2 — worker:**

```powershell
cd backend
.\.venv\Scripts\python -m learnloop.worker
```

**Terminal 3 — frontend:**

```powershell
cd frontend
npm ci
npm run dev
```

Open [LearnLoop Materials](http://127.0.0.1:3100/materials). Create a course and upload a short UTF-8 `.txt` file or a PDF containing selectable text. Scanned PDFs need OCR first. Uploads are limited to 20 MiB per file and 200 pages per PDF. Follow preparation in Agent activity; published lessons appear in Learn. Upload success means the file was saved; the worker still needs to prepare it. New databases start empty.

### 5. Verify and troubleshoot

- Open [API liveness](http://127.0.0.1:8010/health/live) to check that the API is running.
- Open [API docs](http://127.0.0.1:8010/docs), click **Authorize**, enter the backend `API_TOKEN`, and execute `GET /health/ready`. Expect HTTP 200 and `status: ready`. Readiness checks SQLite, sqlite-vec and a real embedding request; generation is checked for configuration only, so it does not prove the OpenRouter key/model works.
- A 401 response usually means the frontend token differs from the backend token. A missing-token configuration error means `LEARNLOOP_API_TOKEN` is unset. Restart Next.js after editing `.env.local`.
- A readiness 503 response lists the failing service. For embeddings, check Ollama is reachable and `bge-m3` is installed. For missing tables, run `.\.venv\Scripts\python -m alembic upgrade head` from `backend/`.
- If jobs stay queued, start the worker. If generation fails, check your OpenRouter key, available credits and configured model, restart the API and worker after configuration changes, then use the run's available Retry/Resume action.
- Restart the API and worker after changing `backend/.env`. An exported environment variable overrides the matching `.env` value; check for old shell settings if changes appear ignored.

Keep `.env`, `.env.local`, `backend/data/`, local databases and live learner records out of Git. Commit environment examples, code, migrations and dependency lockfiles. Share permitted sample documents and upload them separately on each machine. Stop the API and worker before copying the database for backup, or use SQLite's backup API; copying only a live `.db` can miss WAL changes. This is a local, single-owner prototype and needs account/authorization work before public deployment.

For backend tests, backups and importing an existing workspace, see the [SQLite guide](backend/docs/sqlite-development.md). For component details, see the [backend README](backend/README.md) and [frontend README](frontend/README.md).

## Code map

| Area | Start here | Responsibility |
| --- | --- | --- |
| Expert Agent | [agent.py](backend/learnloop/agents/expert/agent.py), [prompts.py](backend/learnloop/agents/expert/prompts.py) | Turn documents into concepts, relationships, lessons, and private questions |

| Shared policy and state | [domain.py](backend/learnloop/core/domain.py), [events.py](backend/learnloop/runtime/events.py), [repository.py](backend/learnloop/persistence/repository.py) | Eligibility, evidence transitions, validated events, and course-scoped data |
| Application UI | [frontend/src/components/](frontend/src/components/) | Study, practice, map, progress, and public activity display |
| Activity display contracts | [frontend/src/lib/agent-activity/](frontend/src/lib/agent-activity/) | Public events, reducers, and backend/demo adapters; agent execution is in Python |
| Proposal | [proposal/README.md](proposal/README.md) | Supplied proposal, source bundles, course guidelines, and lecture notes |

## Implementation status

The backend is a local, single-owner prototype. Its current workflow uses explicit Python dispatch and SQL checkpoints. SQLite jobs run sequentially. Three-level resources, goal-aware Tutor planning and rubric diagnostics are implemented. The controlled evaluation harness is implemented; human review and the research comparisons remain pending. LangGraph remains future work. See the [evaluation guide](backend/docs/evaluation-harness.md) and the implementation-status table in the architecture guide.
